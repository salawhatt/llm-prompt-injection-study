# Косвенные промпт-инъекции в языковых моделях

Практическая часть курсовой: сравнение **Claude Sonnet 5.5** и **GPT-6 Astra**, защиты **A, B, D, E**.

Репозиторий содержит обычный Python-код, готовые данные, обученные классификаторы и 3 216 сохранённых реальных ответов Cloud.ru. Можно проверить фильтры, пересчитать метрики и восстановить графики **без новых API-запросов**. Генерация исходных документов и служебная инфраструктура проведения платных серий в эту публикацию не включены.

## Запуск

Python 3.11. Создайте окружение и установите зависимости:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py report
```

Другие команды:

```bash
python run.py demo     # Документ, реальные ответы двух моделей, действия защит
python run.py verify   # 14 проверок данных и воспроизводимости результатов
python -m pytest -q    # Автоматические тесты
python run.py train    # Необязательное обучение E на готовых данных
```

`report` создаёт CSV и пять графиков в PNG/SVG в `output/`. Обучение запускается только явно и не заменяет исходную модель. Ключи и доступ к Cloud.ru не нужны.

```text
llm-prompt-injection-study/
├── run.py                         # Запуск отчёта, демонстрации, проверок и обучения

│   ├── annotations.jsonl          # Сохранённые смысловые оценки ответов
│   ├── train.jsonl                # Обучающая выборка для классификатора

├── src/                           # Основная логика
│   ├── experiment_core.py         # Формирование запросов A/B и метрики классификации
│   ├── research_defense.py         # TF-IDF, логистическая регрессия, обработка фрагментов
│   ├── research_evaluation.py      # Оценка ответов, интервалы и статистические сравнения

│   ├── summary.csv                # Сводные показатели эксперимента
│   ├── detector_metrics.csv       # Метрики обнаружения инъекций
│   ├── filter_predictions.csv     # Решения фильтров по отдельным документам

├── tests/

```

В файлах `.jsonl` каждая строка содержит отдельную JSON-запись. `cases.jsonl` хранит основной тест и дополнительные наборы. Сохранённые ответы связаны с документами, моделью, конфигурацией и номером повтора.

При запуске `report` программа читает данные из `data/`, применяет фильтры из `models/` и восстанавливает результаты A/B/D/E. Затем сравнивает их с контрольными таблицами из `reference/` и сохраняет рассчитанные показатели в `output/`. Исходные данные и обученные модели при этом не меняются.

### Результаты запуска

В `output/` создаются следующие таблицы:

| Файл | Содержание |
|---|---|
| `outcomes.csv` | Исходы отдельных испытаний для каждой модели и защиты |
| `main_metrics.csv` | ASR и другие показатели основного теста |
| `clean_metrics.csv` | Правильность ответов на обычных документах |
| `filter_metrics.csv` | Precision, Recall, F1 и ложные срабатывания фильтров |
| `paired_comparisons.csv` | Парные сравнения моделей и защит |
| `factors.csv` | Результаты испытаний с изменением отдельных условий |
| `repeats.csv` | Устойчивость результатов при повторных вызовах |
| `challenge.csv` | Показатели отдельного набора сложных испытаний |

Графики сохраняются в двух форматах, PNG и SVG: `01_asr` (успешность инъекций), `02_clean` (качество обычных ответов), `03_filters` (качество фильтров), `04_categories` (категории атак) и `05_length` (влияние длины документа).

## Защиты

A: ответ по документу без специальной защиты. B: системная инструкция о недоверенном документе и JSON-оформление. D: исходный классификатор перед B. E: классификатор фрагментов перед B. При допуске D/E используют идентичный B-ответ только своей модели, ситуации и повтора. Это производные системные исходы, а не дополнительные вызовы LLM.

## Основной результат

Первый ответ на 180 атакующих документов основного теста:

| Модель | A | B | D | E |
|---|---:|---:|---:|---:|
| Claude Sonnet 5.5 | 112/180 (62,22%) | 0/180 | 0/180 | 0/180 |
| GPT-6 Astra | 6/180 (3,33%) | 0/180 | 0/180 | 0/180 |

D ошибочно блокирует 110/180 обычных документов, E 6/180. Обнаружено соответственно 123/180 и 121/180 атак. На отдельном сложном наборе Sonnet с B/E имеет 1/24 успешную атаку. Нулевой ASR не доказывает полной безопасности.

ASR означает полное нормализованное совпадение ответа с контрольным маркером. Общий показатель включает блокировки в знаменатель, условный учитывает только допущенные запросы с ответом. Полезность оценивается отдельно по строгому совпадению и по смыслу.
