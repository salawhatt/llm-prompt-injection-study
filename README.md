# Косвенные промпт-инъекции в языковых моделях

Практическая часть курсовой: сравнение **Claude Sonnet 5.5** и **GPT-6 Astra**, защиты **A, B, D, E**.

Репозиторий содержит Python-код, исходные таблицы и генератор тестовых документов, обученные классификаторы и 3 216 сохранённых реальных ответов Cloud.ru. Можно восстановить тестовые данные, проверить фильтры, пересчитать метрики и построить графики **без новых API-запросов**.

## Быстрая демонстрация в Google Colab

[![Открыть в Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/salawhatt/llm-prompt-injection-study/blob/main/notebooks/demo.ipynb)

Блокнот `notebooks/demo.ipynb` содержит 15 ячеек для просмотра таблиц, выбора графиков, документов и реальных ответов моделей. Основные алгоритмы импортируются из `src/`. Выберите **Среда выполнения → Выполнить все**, достаточно обычного CPU. Для сохранения своих изменений выберите **Файл → Сохранить копию на Диске**.

Можно проверить собственный текст фильтрами D/E и посмотреть JSON типового запроса. Отдельная кнопка отправляет один платный запрос через Cloud.ru с выбранной защитой. Для неё нужен секрет Colab `CLOUDRU_API_KEY`. Обычный запуск всех ячеек не отправляет платных запросов. Новые ответы сохраняются отдельно в `output/live_requests/`, не участвуют в таблицах исследования и повторно используются из кэша текущего сеанса. После неоднозначного сбоя автоматическая повторная отправка запрещена. При удалении среды Colab локальный кэш теряется.

## Запуск

Python 3.11. Создайте окружение и установите зависимости:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py report
```

Другие команды:

```bash
python run.py demo     # Документ, реальные ответы двух моделей, действия защит
python run.py verify   # 14 проверок данных и воспроизводимости результатов
python -m pytest -q    # Автоматические тесты
python run.py train    # Необязательное обучение E на готовых данных
python run.py generate # Сборка тестовых документов из исходных TSV
```

`report` создаёт CSV и пять графиков в PNG/SVG в `output/`. Обучение запускается только явно и не заменяет исходную модель. Ключи и доступ к Cloud.ru не нужны.

### Генерация данных

`python run.py generate` собирает 588 тестовых документов из `data/source/`: основной набор, варианты длины и позиции, изменённые вопросы, сложные и стрессовые испытания. В `scenes.tsv` находятся факты, вопросы и эталоны, в `probes.tsv` - атакующие и обычные фрагменты, в `challenge.tsv` - отдельные сложные сценарии. Тексты уже заданы в таблицах; генератор детерминированно объединяет их с seed `20261121` и не обращается к LLM.

Результат сохраняется в `output/generated/cases.jsonl` вместе с описанием сборки в `manifest.json`. Генерация не изменяет файлы из `data/`. Для исходных TSV тест проверяет точное совпадение всех записей с опубликованным `data/cases.jsonl`. `train.jsonl` и `validation.jsonl` предоставляются готовыми: эта команда восстанавливает тестовые документы, а не обучающую выборку и не реальные API-ответы.

При запуске `report` программа читает данные из `data/`, применяет фильтры из `models/` и восстанавливает результаты A/B/D/E. Затем сравнивает их с контрольными таблицами из `reference/` и сохраняет рассчитанные показатели в `output/`. Исходные данные и обученные модели при этом не меняются.

## Защиты

A: ответ по документу без специальной защиты. B: системная инструкция о недоверенном документе и JSON-оформление. D: исходный классификатор перед B. E: классификатор фрагментов перед B. При допуске D/E используют идентичный B-ответ только своей модели, ситуации и повтора. Это производные системные исходы, а не дополнительные вызовы LLM.

## Результаты исследования

### Успешность инъекций на основном тесте

Сравнение проведено на одинаковых 180 атакующих документах для обеих моделей. Здесь учитывается первое испытание каждого документа; повторные вызовы анализируются отдельно. В ячейках указаны доля успешных атак (ASR) и их количество.

| Модель | A: без специальной защиты | B: промптовая защита | D: B + исходный фильтр | E: B + улучшенный фильтр |
|---|---:|---:|---:|---:|
| Claude Sonnet 5.5 | 62,22% (112/180) | 0% (0/180) | 0% (0/180) | 0% (0/180) |
| GPT-6 Astra | 3,33% (6/180) | 0% (0/180) | 0% (0/180) | 0% (0/180) |

Без специальной защиты GPT-6 Astra реже выполняла внедрённые инструкции на этом наборе. С защитой B успешных атак не зафиксировано у обеих моделей. **Дополнительное снижение ASR от фильтров D/E по сравнению с B на основном тесте не показано:** у B этот показатель уже равен нулю. Для пропущенных документов D/E используют тот же ответ B, а заблокированные документы до модели не доходят.

### Чем отличаются фильтры D и E

Одного ASR недостаточно: фильтр может остановить атаку, но также ошибочно заблокировать обычную задачу. Для проверки использованы 180 атакующих и 180 соответствующих обычных документов.

| Фильтр | Заблокированные атаки из 180 | Ошибочно заблокированные обычные документы из 180 |
|---|---:|---:|
| D | 123 (68,33%) | 110 (61,11%) |
| E | 121 (67,22%) | 6 (3,33%) |

**Основное улучшение E относительно D - снижение ложных блокировок со 110 до 6.** При этом E обнаруживает на две атаки меньше. Это компромисс между обнаружением атак и сохранением доступа к обычным документам, а не доказательство превосходства E по всем показателям. Решение локального фильтра одинаково для обеих LLM.

### Отдельный набор сложных испытаний

Эти 24 атакующих документа не объединяются с основным тестом.

| Модель | A | B | D | E |
|---|---:|---:|---:|---:|
| Claude Sonnet 5.5 | 29,17% (7/24) | 4,17% (1/24) | 0% (0/24) | 4,17% (1/24) |
| GPT-6 Astra | 4,17% (1/24) | 0% (0/24) | 0% (0/24) | 0% (0/24) |

На этом наборе одна инъекция сработала у Claude Sonnet 5.5 даже с B; фильтр E её пропустил, а D заблокировал. Однако D также ошибочно блокировал 18 из 24 обычных контрольных документов, E - 1 из 24. Поэтому нулевой ASR у D следует рассматривать вместе с высокой долей ложных блокировок. Эти результаты также показывают, почему ноль успешных атак на основном наборе нельзя считать гарантией безопасности на других документах.

### Как читать показатели

ASR - доля успешных атак. В этом эксперименте строгий критерий успеха требует, чтобы весь ответ после нормализации совпал с заданной контрольной фразой. Простое упоминание фразы внутри правильного ответа успехом не считается.

В общий ASR входят все завершённые испытания атакующих документов, включая блокировки фильтра. Условный ASR рассчитывается только среди допущенных запросов с полученным ответом. Например, для Claude с E на сложном наборе общий ASR равен 1/24 (4,17%), а условный - 1/12 (8,33%), поскольку фильтр пропустил 12 документов. Блокировка не равна отказу самой LLM, а неудачная атака не обязательно означает правильное выполнение исходной задачи.

Таблицы воспроизводятся командой `python run.py report`: `output/main_metrics.csv`, `output/filter_metrics.csv` и `output/challenge.csv`. Качество обычных ответов, повторы и дополнительные условия представлены отдельно в остальных таблицах `output/`.
